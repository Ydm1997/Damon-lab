# 从零搭建个人知识网站：Obsidian + Quartz + GitHub Pages 自动发布流程

## 一、搭建目标

我搭建这个个人知识网站，不是为了单纯做一个博客，也不是为了做一个临时展示页，而是为了建立一个长期可维护的个人知识系统。

这个网站希望解决三个问题：

1. **内容沉淀问题**  
   平时积累了大量技术笔记、项目复盘、工具流程和方法论，如果只散落在聊天记录、Word 文档、临时文件夹里，很难长期复用。

2. **对外展示问题**  
   项目经验、技术能力、工作方法和个人思考，需要一个稳定的公开入口，方便未来求职、合作、交流和展示。

3. **持续更新问题**  
   如果每次发布文章都要手动改网页、手动整理链接、手动上传文件，时间久了就很难坚持。因此网站必须尽可能自动化，最终达到“我只负责写内容，系统负责发布”的状态。

因此，这个网站的核心目标是：

```text
用最轻量的方式，建立一个可长期维护、可自动发布、可持续积累的个人知识网站。
```

---

## 二、最终方案选择

最终采用的技术路线是：

```text
Obsidian 写作
↓
Markdown 管理内容
↓
Quartz 生成静态网站
↓
GitHub 托管项目
↓
GitHub Actions 自动构建
↓
GitHub Pages 自动发布
```

这套方案的优势是：

- 内容全部是 Markdown，长期可迁移；
- Obsidian 负责本地写作和知识管理；
- Quartz 负责把 Markdown 转成静态网站；
- GitHub 负责代码和内容托管；
- GitHub Actions 负责自动构建；
- GitHub Pages 负责公开访问；
- 日常更新只需要一条命令；
- 后续可以绑定自定义域名，形成个人品牌入口。

最终形成的使用方式是：

```text
打开 Obsidian
↓
写文章
↓
把 publish: false 改成 publish: true
↓
运行 npm.cmd run publish-site
↓
网站自动更新
```

## 十二、文章发布控制机制

为了避免草稿误发布，网站采用 `publish` 字段控制发布。

每篇文章顶部都要有 frontmatter：

```yaml
---
title: 文章标题
date: 2026-05-23
category: tech
tags: [标签1, 标签2]
publish: false
summary: 文章摘要
---
```

其中最重要的是：

```yaml
publish: false
```

默认不发布。

当文章写完并确认可以公开后，改成：

```yaml
publish: true
```

这样做的好处是：

```text
草稿可以放在 content 里
但不会出现在网站上
```

需要特别注意：

```text
如果仓库是 Public，GitHub 仓库里的文件本身仍然是公开的。
publish: false 只是控制网站不展示，不代表 GitHub 仓库不可见。
```

因此，真正敏感的内容不要放进公开仓库。

## 十三、配置 Quartz 只发布 publish: true 的内容

打开：

```text
quartz.config.ts
```

找到：

```ts
filters: [
  Plugin.RemoveDrafts(),
],
```

改成：

```ts
filters: [
  Plugin.ExplicitPublish(),
],
```

含义是：

```text
只有 publish: true 的 Markdown 文件才会被 Quartz 构建进网站。
```

这样比 `draft: true` 更安全，因为它采用的是“默认不发布”的策略。

## 十七、generate-index.cjs 完整代码

路径：

```text
scripts/generate-index.cjs
```

完整代码如下：

```js
const fs = require("fs")
const path = require("path")

const rootDir = path.resolve(__dirname, "..")
const contentDir = path.join(rootDir, "content")

const sections = [
  {
    dir: "tech",
    title: "技术笔记",
    description:
      "这里记录嵌入式 Linux、RK3588、SLAM、点云、多传感器、MQTT、Qt/OpenGL 等技术实践。",
  },
  {
    dir: "projects",
    title: "项目案例",
    description:
      "这里整理我参与或主导过的项目案例，重点记录项目背景、核心问题、技术方案、关键难点和项目复盘。",
  },
  {
    dir: "methodology",
    title: "方法论",
    description:
      "这里沉淀项目复盘、技术调试、方案写作、产品分析和职业表达的方法。",
  },
  {
    dir: "resources",
    title: "资源库",
    description:
      "这里放置可复用的模板、清单、框架和工具。",
  },
]

function walkMarkdownFiles(dir) {
  if (!fs.existsSync(dir)) return []

  const result = []

  for (const item of fs.readdirSync(dir)) {
    const fullPath = path.join(dir, item)
    const stat = fs.statSync(fullPath)

    if (stat.isDirectory()) {
      result.push(...walkMarkdownFiles(fullPath))
      continue
    }

    if (!item.endsWith(".md")) continue
    if (item.toLowerCase() === "index.md") continue

    result.push(fullPath)
  }

  return result
}

function parseFrontmatter(text) {
  const meta = {}

  if (!text.startsWith("---")) return meta

  const end = text.indexOf("\n---", 3)
  if (end === -1) return meta

  const raw = text.slice(3, end).trim()
  const lines = raw.split(/\r?\n/)

  for (const line of lines) {
    const index = line.indexOf(":")
    if (index === -1) continue

    const key = line.slice(0, index).trim()
    let value = line.slice(index + 1).trim()

    if (value === "true") value = true
    else if (value === "false") value = false
    else if (value.startsWith("[") && value.endsWith("]")) {
      value = value
        .slice(1, -1)
        .split(",")
        .map((v) => v.trim())
        .filter(Boolean)
    }

    meta[key] = value
  }

  return meta
}

function isPublished(meta) {
  return meta.publish === true || meta.publish === "true"
}

function generateSectionIndex(section) {
  const sectionDir = path.join(contentDir, section.dir)
  const files = walkMarkdownFiles(sectionDir)

  const articles = files
    .map((file) => {
      const text = fs.readFileSync(file, "utf8")
      const meta = parseFrontmatter(text)

      if (!isPublished(meta)) return null

      const relativePath = path
        .relative(contentDir, file)
        .replace(/\\/g, "/")
        .replace(/\.md$/, "")

      return {
        title: meta.title || path.basename(file, ".md"),
        date: meta.date || "",
        summary: meta.summary || "",
        link: relativePath,
      }
    })
    .filter(Boolean)
    .sort((a, b) => String(b.date).localeCompare(String(a.date)))

  let content = `---\n`
  content += `title: ${section.title}\n`
  content += `publish: true\n`
  content += `---\n\n`
  content += `# ${section.title}\n\n`
  content += `${section.description}\n\n`

  if (articles.length === 0) {
    content += `## 文章列表\n\n`
    content += `暂无已发布文章。\n`
  } else {
    content += `## 文章列表\n\n`

    for (const article of articles) {
      content += `- [[${article.link}|${article.title}]]`

      const extra = []
      if (article.date) extra.push(article.date)
      if (article.summary) extra.push(article.summary)

      if (extra.length > 0) {
        content += ` — ${extra.join(" · ")}`
      }

      content += `\n`
    }
  }

  fs.writeFileSync(path.join(sectionDir, "index.md"), content, "utf8")
  console.log(`Generated: content/${section.dir}/index.md`)
}

for (const section of sections) {
  generateSectionIndex(section)
}

console.log("All indexes generated successfully.")
```

## 十八、generate-index.cjs 的核心逻辑

这个脚本主要做几件事：

```text
1. 遍历指定栏目目录

3. 跳过 index.md
4. 读取文章 frontmatter
```

### 2. 创建 GitHub Actions 部署文件

## 二十七、publish-site.cjs 完整代码

路径：

```text
scripts/publish-site.cjs
```

完整代码如下：

```js
const { execSync } = require("child_process")

function run(cmd) {
  console.log(`\n> ${cmd}`)
  execSync(cmd, { stdio: "inherit" })
}

function getTimestamp() {
  const now = new Date()
  const pad = (n) => String(n).padStart(2, "0")

  const y = now.getFullYear()
  const m = pad(now.getMonth() + 1)
  const d = pad(now.getDate())
  const h = pad(now.getHours())
  const min = pad(now.getMinutes())

  return `${y}-${m}-${d} ${h}:${min}`
}

try {
  run("npm run gen")
  run("npx quartz build")

  run("git add .")

  let hasChanges = true
  try {
    execSync("git diff --cached --quiet", { stdio: "ignore" })
    hasChanges = false
  } catch {
    hasChanges = true
  }

  if (!hasChanges) {
    console.log("\nNo changes to publish.")
    process.exit(0)
  }

  const message = `update site content ${getTimestamp()}`
  run(`git commit -m "${message}"`)
  run("git push origin main")

  console.log("\nPublish completed. GitHub Actions will deploy the site automatically.")
} catch (err) {
  console.error("\nPublish failed.")
  process.exit(1)
}
```

## 三十一、常见问题与解决方式

### 1. localhost 打不开


解决：

```cmd
cd C:\Users\YuanDaming\Desktop\DamingLab\daming-lab
```

### 2. PowerShell 不能运行 npm

错误类似：



### 3. GitHub push 失败

可能原因：

```text
网络连接 GitHub 不稳定
Git 版本过旧
GitHub 认证失败
代理设置异常
```

可尝试：

```cmd
git --version
git remote -v
git push origin main
```

如果 Git 版本过旧，升级 Git for Windows。

---

### 4. GitHub Actions build 绿、deploy 红

常见原因：

```text
GitHub Pages 没有启用
Source 没有选择 GitHub Actions
workflow 中缺少 configure-pages
```

检查：

```text
Settings → Pages → Source → GitHub Actions
```

并确认 `deploy.yml` 中包含：

```yaml
- name: Setup Pages
  uses: actions/configure-pages@v5
```

---

### 5. 文章没有出现在栏目页

检查文章顶部是否有：

```yaml
publish: true
```

然后运行：

```cmd
npm.cmd run gen
```

或者直接运行：

```cmd
npm.cmd run publish-site
```

---

### 6. 草稿没有发布

这是正常现象。

如果文章顶部是：

```yaml
publish: false
```

就不会进入网站。

---

### 7. GitHub 仓库里还有草稿

这是需要注意的问题。

`publish: false` 只能阻止 Quartz 发布网页，但如果仓库是 Public，文件本身仍然能在 GitHub 仓库里看到。

因此：

```text
不要把真正私密、敏感、未脱敏的内容放入公开仓库。
```
