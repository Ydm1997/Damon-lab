# 从零搭建个人知识网站：Obsidian + Quartz + GitHub Pages 自动发布流程

## 一、搭建目标

我搭建这个个人知识网站，不是为了单纯做一个博客，也不是为了做一个临时展示页，而是为了建立一个长期可维护的个人知识系统。

这个网站希望解决三个问题：

1. **内容沉淀问题**  
   平时积累了大量技术笔记、项目复盘、工具流程和方法论，如果只散落在聊天记录、Word 文档、临时文件夹里，很难长期复用。

2. **对外展示问题**  
   项目经验、技术能力、工作方法和个人思考，需要一个稳定的公开入口，方便未来求职、合作、交流和展示。

3. **持续更新问题**  
   如果每次发布文章都要手动改网页、手动整理链接、手动上传文件，时间久了就很难坚持。因此网站必须尽可能自动化，最终达到“我只负责写内容，系统负责发布”的状态。

因此，这个网站的核心目标是：

```text
用最轻量的方式，建立一个可长期维护、可自动发布、可持续积累的个人知识网站。
```

---

## 二、最终方案选择

最终采用的技术路线是：

```text
Obsidian 写作
↓
Markdown 管理内容
↓
Quartz 生成静态网站
↓
GitHub 托管项目
↓
GitHub Actions 自动构建
↓
GitHub Pages 自动发布
```

这套方案的优势是：

- 内容全部是 Markdown，长期可迁移；
- Obsidian 负责本地写作和知识管理；
- Quartz 负责把 Markdown 转成静态网站；
- GitHub 负责代码和内容托管；
- GitHub Actions 负责自动构建；
- GitHub Pages 负责公开访问；
- 日常更新只需要一条命令；
- 后续可以绑定自定义域名，形成个人品牌入口。

最终形成的使用方式是：

```text
打开 Obsidian
↓
写文章
↓
把 publish: false 改成 publish: true
↓
运行 npm.cmd run publish-site
↓
网站自动更新
```

---

## 三、整体架构

整个系统可以理解为五层：

```text
第一层：内容输入层
Obsidian / Markdown

第二层：内容管理层
content 目录 / Frontmatter / publish 字段

第三层：网站生成层
Quartz

第四层：自动化层
generate-index.cjs / publish-site.cjs / GitHub Actions

第五层：发布访问层
GitHub Pages / 自定义域名
```

对应关系如下：

| 层级 | 工具 | 作用 |
|---|---|---|
| 写作层 | Obsidian | 写 Markdown 文章 |
| 内容层 | content 目录 | 存放所有网站内容 |
| 生成层 | Quartz | 将 Markdown 转成静态网页 |
| 托管层 | GitHub | 管理项目代码和文章 |
| 自动化层 | GitHub Actions | 自动构建和部署 |
| 发布层 | GitHub Pages | 提供公网访问地址 |

其中：

- Git：提交和推送项目；
- Obsidian：本地 Markdown 写作；
- VS Code / 记事本：修改配置文件和脚本。

### 2. 检查环境版本

打开 CMD，执行：

```cmd

npm -v
git --version
```

本次搭建时的版本为：


如果出现：

```text
'node' 不是内部或外部命令，也不是可运行的程序
```

说明 Node.js 没装好，或者没有加入系统环境变量。


通常也是 Node.js 没装好，因为 npm 会随 Node.js 一起安装。

如果 Git 版本较旧，可能会出现 GitHub 推送失败、认证异常、SSL 连接中断等问题，建议升级 Git for Windows。

## 十、文章发布控制机制

为了避免草稿误发布，网站采用 `publish` 字段控制发布。

每篇文章顶部都要有 frontmatter：

```yaml
---
title: 文章标题
date: 2026-05-23
category: tech
tags: [标签1, 标签2]
publish: false
summary: 文章摘要
---
```

其中最重要的是：

```yaml
publish: false
```

默认不发布。

当文章写完并确认可以公开后，改成：

```yaml
publish: true
```

这样做的好处是：

```text
草稿可以放在 content 里
但不会出现在网站上
```

需要特别注意：

```text
如果仓库是 Public，GitHub 仓库里的文件本身仍然是公开的。
publish: false 只是控制网站不展示，不代表 GitHub 仓库不可见。
```

因此，真正敏感的内容不要放进公开仓库。

## 十一、配置 Quartz 只发布 publish: true 的内容

打开：

```text
quartz.config.ts
```

找到：

```ts
filters: [
  Plugin.RemoveDrafts(),
],
```

改成：

```ts
filters: [
  Plugin.ExplicitPublish(),
],
```

含义是：

```text
只有 publish: true 的 Markdown 文件才会被 Quartz 构建进网站。
```

这样比 `draft: true` 更安全，因为它采用的是“默认不发布”的策略。
